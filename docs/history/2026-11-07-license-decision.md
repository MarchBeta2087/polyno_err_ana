# 决策记录：维持单许可（不做商业双许可）

- 日期：2026-11-07
- 状态：**已决定**
- 决策人：项目维护者（唯一版权人）

## 背景

项目以 GPL-3.0-or-later 发布。曾评估「同码双许可」（GPL + 付费商业许可）的可行性：
需要 CLA/版权归集、合同模板、定价与开票流程，并要处理静态链接 MPFR/GMP（LGPL）的额外义务。

## 决策

**不提供商业双许可**，维持单一 GPL-3.0-or-later。

## 理由

1. 目标用户以研究/工程计算为主，闭源嵌入需求不明确，商业授权预期收益低于维护成本；
2. 双许可要求严格的贡献者权利管理（CLA），与当前「轻量、单人维护」的模式冲突；
3. 已发布版本的 GPL 授权不可撤回，双许可只能约束未来，边际价值有限。

## 影响与后续约定

- 想闭源集成者：用「独立进程调用 CLI + stdin/stdout」的方式，或按 GPL 合规分发；
- 贡献策略采用「入站=出站」，不引入 CLA；
- 将来若要更换许可（如 MIT/Apache-2.0），仍需**所有外部贡献者**同意，因此在
  `CONTRIBUTING.md` 中明确提示：不要引入与 GPL 不兼容的代码；
- 如需重新评估，可基于本文件恢复讨论。
