# 《需求分析.md》修改建议（v0.1 → v0.2）

按“位置 / 问题 / 建议文字”组织，可直接替换原文章节。标 **[阻塞]** 的会直接导致实现返工。

## 1. §2 术语表：补“展开对象”与 `k` 的定义

**问题**：§3.6 说“将 `δf` 关于 `δv` 展开为首项 `a·δv^k`”，但 §2 又把 `δf` 定义为**已线性化的一阶量** `f'(x)·δx`。对 `f'(x)≠0` 的情形这个展开恒为 `k=1`，分类退化成只看 `sign(f')`；对 `f'(x)=0` 则恒为 `0`，会被规则 2 误判成 `Finite`。

**建议在 §2 表格后新增**：

```text
g(δv)  精确差函数：绝对模式下 g(δv) = f(v±δv) − f(v)（R± 取同号），
       相对模式下 g(δv) = 上式 / |f(v)|；复数变量取模 |g(δv)|。
k, a   g(δv) 关于 δv 的 Laurent 展开中**首个非零项**的指数与系数，
       即 g(δv) = a·δv^k + o(δv^k)；若 g ≡ 0，记 k = ∞（无影响）。
```

并把 §2 的 `δf` 一行明确为“**仅用于显示**的线性化一阶量，不参与极限分类”。

## 2. §3.6 **[阻塞]**：分类对象改为 `g(δv)`，并补非整数 `k` 的规则

**问题**：
- 规则 3/4 用 `sign(δv^k)`，但 §3.6 最后的边界要求承认 `k` 可以是分数（`(1+x)^(1/2)` 在 `x=-1` 时 `k=1/2`），此时 `δv<0` 在实数域无定义，规则 3/4 无输出。
- 规则 2 “`k == 0` → `Finite`” 无法区分“常驻有限”与“恒为 0”（`g ≡ 0`）。

**建议改写为**：

```text
分类输入为 §2 定义的 g(δv)，不是线性化形式 δf。

1. 在 v 的估计点展开 g(δv)，取首个非零项 a·δv^k（k 可为负、零、正、有理）。
2. g ≡ 0（f 不依赖 v，或该点 f 恒定）        → Finite
3. k == 0                                     → Finite
4. k ∈ ℤ 且 k > 0：δv→±0 为 PosZero/NegZero（符号 = sign(a)·sign(δv^k)）；
                    δv→±∞ 为 PosInf/NegInf（符号同上）
5. k ∈ ℤ 且 k < 0：δv→±0 为 ±Inf，δv→±∞ 为 ±Zero
6. k ∉ ℤ（有理非整数）：
   - δv → +0：sign(a) 定性，PosZero / NegZero
   - δv → -0：实数域无定义 → Undefined（复数变量按模，仍给 Zero/Inf）
7. 相对形式的 δf/f：分子分母阶数（k 相同）相等 → Finite；
   分子高阶 → Undefined；分子低阶 → PosInf/NegInf。
```

## 3. §6 T-9 **[阻塞]**：验收点与公式矛盾

**问题**：`f=(1+x)^2`, `x=-1` 展开得 `g(δx)=δx²`（偶次幂，严格对称），四组 `LimState` 必然只有 `PosZero/PosZero/PosInf/PosInf` 两种类型，不可能“四组各异”。

**建议改为**：

```text
| T-9 | ... -f (1+x)^2 --estimated x=-1 --lim all | g(δx)=δx²，k=2≠1：
  δf 线性化形式为 0 但分类必须给 PosZero/PosZero/PosInf/PosInf，不得判 Finite
| T-9b | ... -f (1+x)^3 --estimated x=-1 --lim all | g(δx)=δx³，k=3 奇次：
  +0→PosZero, -0→NegZero, +∞→PosInf, -∞→NegInf（四组各异）
```

## 4. §3.3 **[阻塞]**：多变量时“五行”到底是谁的五行

**问题**：原文“对每个变量 `v` …… 输出以下五行”，但 `δf` 是全体变量的函数；`n>1` 时五行按变量重复会让 `δf` 出现 `n` 个不同版本，且与 §3.4“只变动当前分析的那一个变量”耦合不清晰。

**建议在 §3.3 开头替换为**：

```text
§3.3 输出分两层：
(a) 全局块（每个公式一份）：
    f(x) = ...
    δf   = Σ_i ∂f/∂v_i · δv_i + O(δ²)
    δf/f = δf / f + O(δ²)          ← 分母必须是 f（R-1）
(b) 逐变量块（每个变量一份）：
    ∂f/∂v_i, δv_i, δv_i/v_i, |∂f/∂v_i|·δv_i（单变量扰动贡献）
    δ_{R±}f、δ_{R±}f/f（仅该变量扰动，其余固定在估计点）
    LimState 分类表
```

## 5. §3.4 措辞：修掉“每个极限状态无关”

**原文**：“对每个变量、每个极限状态无关，始终输出”
**建议**：“不随 `LimState` 变化，对每个变量恒输出下列四行”。

同时把“`f(v)=0` 时相对形式标 `N/A`（或 `Inf`）”改为单一确定行为：

```text
若 |f(v)| == 0：δ_{R±}f/f 输出 N/A（原因：f(v)=0），不输出 NaN/Inf 数值。
```

## 6. §3.6 **[阻塞]**：`LimitType` 与 T-6 的标签不一致

**问题**：枚举只有 6 值，但 T-6 期望 `ComplexZero/ComplexInf`。

**建议**：二选一，推荐方案 A。

```text
方案 A（推荐）：复数变量复用 Zero/Inf 语义，标签记为 CZero/CInf：
  LimitType = {Finite, PosZero, NegZero, PosInf, NegInf, CZero, CInf, Undefined}
方案 B：T-6 验收点改为“输出 Finite / CZero / CInf 之一”，删去 Pos/Neg 前缀要求。
```

## 7. §3.1 **[阻塞]**：缺少精度、默认行为、退出码

**问题**：整套“任意精度内核”没有精度选项；`--vars` 未给时的默认输出未定义（但 T-1…T-9 的命令都没写 `--vars`）；`--estimated` 缺失时的行为未定义。

**建议在选项表补三行**：

```text
| -p, --precision INT | 内核工作精度（bit），默认 256 |
| (默认)              | 不给 --vars 时输出 §3.3(a) 全局块 + §3.4 边界，符号推导不展开 |
| --estimated 缺失    | 符号行数值列输出 N/A；R± 与极限分类照常计算（v=0） |
```

**新增小节 §3.8 退出码**：

```text
0 成功；1 解析错误（含列号）；2 命令行错误（冲突/未声明变量）；3 内核数值异常。
错误一律写 stderr，正常结果写 stdout。
```

## 8. §3.1 选项语义：`-R/-C` 里的 `{--absolute|--relative}` 应删除

**问题**：`-R, --real {--absolute|--relative} VARNAME ERR` 把全局模式塞进了单变量语法，导致 `-R x 1e-4 y 1e-4` 到底“每对前是否都要给模式”无法判定。

**建议**：

```text
-R, --real VARNAME ERR [VARNAME ERR ...]    可多次出现，累计；同名重复报错
-C, --comp VARNAME RE_ERR IM_ERR [...]       同上
误差模式仅由 -a/-r 全局决定，出现位置任意，与 -R/-C 顺序无关。
```

并补 `--estimated` 的复数写法与结合性说明（见下条）。

## 9. §3.2 语法：补优先级表与几个未定义点

**建议新增**：

```text
优先级（低→高）： + -  <  * /  <  一元 -  <  ^（右结合）
指数常数的取值域：实数或复数；2^-1、a^(-2) 合法；(1+i) 合法。
--estimated 语法：VARNAME=VALUE，VALUE 同 FORMULA 的常量语法（支持 1+2i、-0.6）。
负数底数 + 非整数指数（如 (-8)^(1/3)）：
  默认走 §3.5 的复数主值 + -k；如需实根，用 --real-root 开关切到实数分支。
```

**问题**：这条是当前最大的语义黑洞——`(-8)^(1/3)` 是 `-2` 还是 `2·e^{iπ/3}`，直接决定 `δf` 与 R± 是否一致。

## 10. §3.6 `--lim SPEC` 的写法在 shell 下有歧义

**问题**：`--lim x:+0` 中的 `+0` 在 zsh 下可能被当作通配/路径；`∞` 也无法键入。

**建议**：

```text
--lim all            等价于下面每个变量 4 个状态
--lim VAR:p0|n0|pinf|ninf
也接受 --lim VAR:+0 等（需引号），文档中标 p0/n0/pinf/ninf 为规范写法。
```

## 11. N-1 行数约束与需求范围冲突

**问题**：解析器 + 符号微分 + Laurent 展开 + 双内核抽象 + 分类 + 格式化，1200 行很难容纳，且“单文件”含义不明。

**建议改为**：

```text
N-1 实现代码总量 ≤ 2500 行（不含 tests/、第三方内核），单文件 ≤ 800 行；
    核心算法（AST、微分、首项提取）不得依赖第三方符号库。
```

---

## 12. §3.7 数值格式：把“或”定死

**问题**：`{:.6g}` 或 `{:.4e}` 二选一不可验收。

**建议**：`|x| ∈ [1e-4, 1e6)` 用 `{:.6g}`，否则 `{:.4e}`；`0` 输出 `0`（不输出 `0.000000`）。

---

## 13. §3.5 分支号：`k` 的适用范围需排除整数指数以外的实数幂

**问题**：“对所有非常数幂统一作用”与“整数实指数时无分支”并存，但 `(1+x)^(-2)` 这类负整数同理应无分支；`(a+b)^(1/2)` 在底数为正时 `k` 也会让结果跑出实轴。

**建议补一句**：

```text
当且仅当 底数∈ℝ⁻ 且 指数非整数，或 底数∈ℂ 时，k 才参与；
k 非 0 时输出顶部加一行 `branch k = <k>`，避免与默认结果混淆。
```
